# 2026龙芯杯二等奖设计仓库

## 经验分享

哈工深在2026龙芯杯的个人赛获奖很好，3人国一，4人国二，7人国三。但是考虑到去年增加了奖项之后导致今年人数暴涨，而今年的获奖情况又这么好，预计参加人数会进一步上升，想要参加的人得做好卷性能与打榜的准备。而当你进入决赛之后，决赛历年都是一道简单的算法题(例如，求一个数组中的最大值)，然后使用 Loongarch 汇编语言编写(或者使用 C 编译成汇编语言)。但是总体来说，个人赛的性价比远高于团体赛，既不吃队友，也没有0.8的折扣加分，要花的时间也少，跑的测试也少。

对于准备来说，准备周期大概在8个月左右，我是从1月开始准备，到8月末。今年相对于去年主要是增加了 WNS > 0 的限制，去年没有这个限制导致大家都在超频，今年增加这个测试后给了复杂架构的 CPU 更多生存空间。不过我还是推荐做顺序双发射的 CPU ，既能兼顾高主频与高 IPC，乱序发射不仅架构复杂，而且容易出问题。因为在决赛截止提交后会有一个 Alpha 的复测，一旦出现问题，整个测试算作零分，直接空悲切。所以从各种角度都是做顺序双发射更具性价比。

展望明年的话，龙芯杯个人赛官方可能会大改测试的架构(决赛的测试已经用了很多年了)，而且测试程序都是公开可见的，导致很多预取，打表的针对性优化。预测可能会增多测试的标准，例如测试 IPC ，在测试中加入随机因子限制打表，但是总体实现量还是要比团体赛少很多，同时本质也还是一个打榜比赛。

代码方面，推荐使用 Agent ，我是使用 Codex 辅助打比赛，在我的 Workflow 中，是让 codex 搭建了一整套仿真测试框架，针对四个测试程序进行仿真，在测算正确性的同时测算IPC，还将程序中的停顿统计出来，针对其中的停顿进行针对性优化。然后在设备方面，我是使用 Mac Ssh 链接到我的另一台 Arch Linux 主机上，在 Arch Linux 上安装 Vivado 并搭建工作测试环境。通过这种操作，就可以在 Mac 上编写代码，并让 codex 自动进行 simulation, implmention, generate_bitstream。这样就可以让 codex 自动化测试，自动化修改，如果可以的话，你甚至可以写一个脚本让 codex 自动提交到对应的网站并读取对应的成绩，达成真正的自动化。不过你可以不熟悉具体的实现，但你要熟悉你想要的架构是什么，你想要做一个什么样的操作,需要做好 code-review，成为好的 codex 使用者，否则会影响 Agent的发挥。如果你现在想先了解，可以先加入龙芯杯竞赛 QQ 群 583344130 先行了解。
